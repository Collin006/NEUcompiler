一、项目概述

- 项目名称：NEUcompiler（教学级简易编译器）
- 目标：实现从源代码到中间表示（四元式）并生成目标代码的完整流程；具备词法分析、语法分析与语义处理、四元式生成、中间代码局部优化、目标代码生成等模块，便于教学与验证编译器原理。
- 支持的语言子集（实现范围示例）：算术/逻辑表达式、赋值、条件与循环控制、函数入口/返回（以标记/四元式形式）、基本输入/输出（视具体实现）。详细语法可见 `docs/文法.md`。

二、系统整体架构（高层）

流程：
1. 词法分析 —— `lexicalAnalyze.cpp`
2. 语法/语义分析与四元式生成 —— `parser.cpp`、`parser.h`（由 `Parser::emitQuad` 等语义动作产生原始四元式）
3. 符号表与类型管理 —— `synbl.cpp`、`synbl.h`、`global.*`
4. 四元式（中间表示） —— `four_tuple.h`
5. 四元式优化（局部/基于基本块） —— `youhua.CPP`、`youhua.h`
6. 目标代码生成 / 输出 —— `code_builders.cpp` 与 `global.cpp` 等（`CodeBuilder` 使用优化/标注后的 `MarkedFourTuple` 和 `ActiveRecord` 生成目标指令）

主要入口：`main.cpp`（读取输入文件，驱动词法/语法/优化/输出流程）。

三、主要源码文件与职责映射

- `lexicalAnalyze.cpp`：实现分词、关键字/标识符/常量识别。
- `parser.cpp` / `parser.h`：语法分析（含语义动作），生成四元式序列。
- `four_tuple.h`：定义 `FourTuple`、`BasicBlock` 等中间表示的数据结构。
- `code_builders.cpp` / `.h`：目标代码生成器。从优化/标注后的四元式（`MarkedFourTuple`）和活跃记录（`ActiveRecord`）构建目标指令序列（参见 `CodeBuilder::Init`、`BuildTokens`、`BuildTwoOperandsToken` 等）。
- `synbl.cpp` / `.h`：符号表、类型检查、作用域管理。
- `youhua.CPP` / `.h`：四元式级别的优化器，负责基本块划分与若干局部优化规则。
- `global.*`：保存全局状态、输出路径与辅助功能。

四、关键数据结构

- FourTuple（四元式）：通常包含 `operator_str`（运算符）、`first_value`、`second_value`、`dist`（目标）。示例：("+","a","b","t1") 表示 t1 := a + b。
- BasicBlock：包含 `id`、`tuples`（块内四元式序列）、`prev` / `next`（前驱/后继块集合），用于构造控制流并进行局部优化。

五、优化器（`youhua.CPP`）实现要点

优化器设计：先将四元式划分为基本块（Basic Block），再在每个基本块内按顺序执行一组局部优化规则（常量折叠 / 代数简化 / 公共子表达式消除 / 再次折叠 / 死代码消除），最后将优化后的块拼回为新的四元式序列。

主要优化规则简述：
- 常量折叠（constantFolding）：对操作符和操作数均为常量的表达式直接计算并替换为赋值四元式（":=")；注意处理除零与逻辑比较返回 0/1 的情形。
- 代数简化（algebraicSimplify）：应用恒等律（x+0 -> x，x*1 -> x，x*0 -> 0，x/1 -> x 等），把相应的表达式替为简单赋值。
- 公共子表达式消除（CSE，commonSubexpressionElimination）：以字符串 key(op_first_second) 标识表达式，若相同表达式已有临时量结果，生成赋值复用该临时量；在遇到对变量赋值时使含该变量的表达式 key 失效。
- 死代码消除（deadCodeElimination）：做后向活跃变量分析（在基本块范围内），删除那些定义了但未被后续使用的赋值语句。
- 基本块划分（buildBasicBlocks）：识别基本块入口（leader）规则：程序开始、函数入口标签 `(lb, label, , )`、跳转目标、控制流语句之后的下一条语句等；对跳转目标做了字符串/整数的安全判断以避免对非数字字符串调用 stoi 导致异常。

健壮性改进（在 `youhua.CPP` 中）：
- 增加 `Utils::isIntegerIndex`，在调用 `std::stoi` 前判断字符串是否为严格整数形式，避免 "stoi: no conversion" 的异常。
- 对标签（函数入口）使用 `first_value` 建立 `label2idx` 字符串->下标映射，从而支持以字符串标签跳转与数字下标两种形式。

七、示例：片段 Before / After（用于现场演示）

原始四元式（示例片段）：
- ("*","3","5","t1")
- ("+","t1","10","t2")
- (":=","100","","x")
- ("+","a","b","t3")
- ("+","a","b","t4")
- ("+","t3","0","t5")
- ("*","t4","1","t6")
- (":=","t5","","result")

优化后（示意）：
- 常量折叠：t1 := 15
- 代数简化：t5 := t3；t6 := t4
- 公共子表达式消除：t4 的计算重用 t3，生成 t4 := t3 或在后续用 t3 替换 t4
- 死代码消除：若 x 未被使用，删除 x := 100

八、已知限制与后续改进建议

当前实现的限制：
- 优化多为基本块内部局部优化，缺少全局数据流分析（跨块 CSE、全局常量传播、全局死代码消除等）。
- CSE 使用字符串匹配，遇到表达式重命名、等价但文本不同的表达式时可能失效。
- 目标代码生成为教学/示例级别，尚未实现寄存器分配、指令选择优化等高级后端功能。
- 错误恢复机制简单，可改进为带位置/行号的更友好的错误报告与回溯修复。

后续可选改进：
- 引入 SSA（静态单赋值）形式以简化与增强优化效果；实现跨基本块的全局优化。
- 实现寄存器分配（图着色或线性扫描），并改进指令选择以生成更高效目标代码。
- 扩展语法支持（函数、数组、复合类型、参数传递、作用域嵌套等）。
- 增加自动化回归测试并集成 CI。
